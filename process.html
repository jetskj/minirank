MiniRank Development Process Document

AI Coding Assessment — Phase 8
Candidate Process Report
Project: MiniRank (Keyword Position Tracker)
Tech Stack: Plain PHP 8, SQLite PDO, Vanilla JavaScript
Estimated Effort: ~8–10 hours

1. Plan & Key Decisions

Before writing code, a structured modular plan was established (stored in Plan.md and expanded in Plan2.md):

  • Architecture: Single front controller pattern (public/index.php) adhering strictly to Plain PHP 8 without heavy frameworks to maintain simplicity and leverage free model context windows effectively.
  • Database: SQLite database located at data/minirank.sqlite managed via PDO with strict prepared statements and foreign key constraints.
  • Security: Parameterized queries for all SQL operations, strict input sanitization, output escaping using htmlspecialchars(), and CSRF protection tokens on state-changing requests.
  • Features Scope: Implemented all must-haves (M1–M6, M8) and multiple stretch goals (S1–S5, S8) including Chart.js visualization, multi-project context, user accounts, advanced filtering, and CSV export.

Hindsight Reflection: Starting with a clear multi-phase roadmap prevented scope creep and kept code diffs minimal and reviewable. However, early planning for authentication and multi-project relationships saved refactoring time later.

2. Prompts & Fixes (Key Interactions & Debugging)

During development, multiple AI models were leveraged. Below are 3 real prompts that mattered, including a critical failure and recovery:

Prompt 1: Database Schema & Seeding (Success)

"Generate a SQLite schema script and a PHP seed script that creates demo keywords with ~30 days of daily positions (1-100) using prepared statements and ON CONFLICT upsert logic."

Outcome: Successfully generated db/schema.sql and seeds/seed.php, establishing a solid foundation for historical trend calculation.

Prompt 2: Frontend Refresh Persistence & State Bug (Failure & Recovery)

Initial model (Nemotron) struggled with state synchronization between AJAX position refreshes and UI re-renders, causing browser page refreshes to reset state or lose persistence. After multiple failed iterations, Gemini 3.5 Flash Lite was used with this prompt:

"Please read @Plan.md I just did phase 6 and a bit of phase 7. There is a problem with the frontend. When I refresh the page in the browser, everything resets back to a previous state. Please fix it, whenever I click the button in the refresh next to an entry, it should stick, and never revert back."

Outcome: Gemini correctly corrected the database query to display the latest position (positions[0]) rather than the oldest 7-day position and ensured proper persistence via POST to api/positions.php stored in SQLite.

Prompt 3: User Accounts & CSRF Protection (Success)

"Implement user authentication (register, login, logout with password hashing and sessions) and CSRF protection across all state-changing forms and AJAX endpoints."

Outcome: Secured all endpoints with header/token validation and added robust user management in core/auth.php.

Prompt 4: UI/UX Design Overhaul & Mobile Responsiveness (Success)

"can you make the site look a bit more ok? i dont want a super futuristic site but a bit more aesthetically pleasing. dont break it, just change it a little bit. make sure it still works on the phone aspect ratio"

Outcome: After all core features and stretch goals were fully coded, the AI overhauled the design across public/assets/style.css and public/index.php, introducing a clean SaaS aesthetic with card containers, soft shadows, polished buttons, subtle trend badges, and robust mobile aspect ratio responsiveness with horizontal table scrolling.

3. Retrospective

What would be done differently: Establish automated unit tests (S6) earlier in the development lifecycle rather than focusing primarily on feature parity and UI stretch goals.

AI Agent Experience: Using opencode with different models highlighted the importance of model selection. Smaller models required precise, incremental prompts, while fallback to larger context windows (Gemini Flash Lite) efficiently resolved stubborn state bugs in one shot.

Total Time Spent: Approximately 8–10 hours of actual effort.
